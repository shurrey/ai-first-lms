## Goal
Stop letting the client assert who it is when opening a session.

## Context
- `engine/api/session.py::_DEMO_PERSONS` maps persona+course to a hardcoded person (spec.md §2).

## Acceptance criteria
Copied from spec.md; the source section is in parentheses after each item.
- [ ] `POST /api/session` request body drops `persona` and `person_id`; persona = `active_role`, person = authenticated person.
- [ ] `course_id` must be one the user may act in: enrolled for student/faculty, any course containing an advisee for advisor, any course for admin. `"all"` is allowed only for advisor/admin.
- [ ] `_DEMO_PERSONS` is deleted. `_COURSE_SLUG_TO_UUID` is replaced with a DB lookup on course node slugs.
- [ ] No UI path lets a user choose to act as a different person (§4.8, together with T-F-101/T-F-102).
