# T-C-108 — Every persona reaches the agents its job needs

**Workstream:** integration
**Phase:** 1 (spec.md §19.1)
**Size:** S
**Status:** applied on round2/phase0 (decided by Scott 2026-10-02)
**Spec:** spec.md §4.5, §5.2, §17, §18
**Dependencies:** T-C-106, T-E-106

## Goal
Admin questions about the grading pipeline and issued credentials reach an agent that can answer them, without giving admin the write tools those agents carry.

## Context
- Split out of T-C-106. A routing probe of real UI prompts found admin "grading pipeline" and "credentials issued" questions now route to `engagement_analyst` instead of `grading_assistant` / `assessment`.
- Admin was left out of those agents' `persona_scope` because both list write tools (`assessments.commit_grade`, `assessments.approve_credential`).
- The tool gateway now enforces each tool's Allowed roles from `contracts/mcp-tools.md`, so per-tool roles can keep admin off those writes even if admin can reach the agent. §17 gives admin badge revoke but no grade commit or badge approve.

## Acceptance criteria
- [ ] A human decides whether admin gets `assessment` and/or `grading_assistant` in `persona_scope`.
- [ ] If yes: `contracts/agent-manifests.yaml` and `src/agents/*/manifest.yaml` updated, and `contracts/mcp-tools.md` Allowed roles on every write tool those agents list exclude `admin` except where §17 grants it, each with a `- Change: T-C-108` line.
- [ ] `test_scopes_cover_real_persona_flows` in `src/engine/tests/test_guardrail_wiring.py` updated to the decision.
- [ ] `check_contracts.py` green; `uv run pytest src/engine -q` green.

## Decision (2026-10-02)
"All users should be able to interact with the orchestration agent and access the agents they need. No persona should be blocked from accessing the agents they need to do their job." Agent persona_scope is broad; protection is at the tool level (ToolGateway allowed roles, object-level scope, write-gates). Admins may approve badges (an instructor may leave).

## Applied
- persona_scope widened: assessment +admin, advisor, program_lead; grading_assistant +admin; advising +admin, program_lead; accessibility +advisor, program_lead; early_alert, engagement_analyst, communication +program_lead; course_architect +admin, program_lead.
- mcp-tools.md: the new roles added to those agents' **read** tools only (25 tools, each with a `- Change: T-C-108` line). Write tools unchanged.
- assessments.approve_credential Allowed roles: faculty (own course), admin; advisor and instructional_designer removed. `badge_approve` capability granted to admin.
- Per-persona default agent: student/faculty tutor, advisor advising, admin and program_lead engagement_analyst.
- Verified: 29 job prompts across all five personas through the live classifier route to allowed agents with usable tools (0 failures); live turns for program_lead, admin and advisor complete without permission_denied.
