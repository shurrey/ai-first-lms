## What needs to change
- `contracts/mcp-tools.md`, `assessments.list_submission_history`:
  - Input: `person_id` becomes optional for `faculty` when `course_id` is given (all learners'
    submissions in that course, optionally one `assignment_node`). Students still list only
    their own (the gateway forces `person_id` to self).
  - Output: each row also carries `person_id`, `rubric_id` (the assignment node's
    `metadata.rubric_id`) and `assignment_title`.
- Alternative with the same effect: grant `grading_assistant` `roster.list_by_course` and an
  assignment-by-title lookup. That widens the agent's surface more, so the first option is
  preferred.

## Why it's needed
"Grade submissions for Essay 3 with my rubric." (spec.md §21, SPEC-v1 §9 scenario 3) needs the
grading assistant to find Essay 3's submissions and its rubric. Today the tool requires a
`person_id`, grading_assistant has no roster tool, and no tool maps "Essay 3" to an assignment
node or a `rubric_id` (`assessments.get_rubric` needs one). The seed already has CS 101
"Essay 3: Algorithms and Accountability" with a 4-criterion rubric and 6 learners' submissions.

## Impact
- Data & MCP: `src/data_mcp/mcp_servers/assessments/tools.py` (person filter optional, extra
  columns) and its contract tests.
- Engine: the gateway already requires `course_id` for every non-admin, non-student caller of
  this tool and checks it against the caller's courses, so a person-less faculty call stays
  course-bound. Unreleased `ai_score` masking for students is still open (T-D-104).
- Agents: grading_assistant prompt lists by course, then `get_rubric` with the row's `rubric_id`.
- Platform: remove `xfail` from `03-grading.yaml`; re-record LLM fixtures.
- Breaking change: no (optional input, added output fields).
