# T-C-106 — agent-manifests.yaml: decide persona_scope now that dispatch enforces it

**Workstream:** integration
**Phase:** 0 (spec.md §19.1)
**Size:** S
**Status:** done
**Spec:** spec.md §3A S5, §4.5, §18
**Dependencies:** T-E-098

## Goal
Make each manifest's `persona_scope` the access policy we actually want, because dispatch now refuses any agent outside it.

## Context
- Before T-E-098, `persona_scope` was never checked. Now `dispatch._execute_step` ends the turn with `error{code:"permission_denied"}` when the persona is outside an agent's scope, and interpret only offers the allowed agents.
- Routes that worked before and are now refused:
  - student: assessment, course_architect, grading_assistant, early_alert, engagement_analyst, communication.
  - faculty: advising.
  - advisor: tutor, content_generator, assessment, course_architect, grading_assistant, accessibility.
  - admin: tutor, advising, content_generator, assessment, course_architect, grading_assistant.
  - Multi-agent patterns that include a refused agent (identify_and_help, syllabus_draft, quiz_generation for advisor and admin).
- Advisor and admin have no general-purpose agent, because tutor is not in their scope. Interpret falls back to `tutor` when it cannot parse a reply, so those turns end in `permission_denied`.
- The 11 scenarios in `src/platform/scenarios/` use only student and faculty routes that are still allowed.

## Acceptance criteria
- [x] A human decides each persona's agent set. Candidates: tutor and content_generator for advisor and admin, assessment for admin (badge questions), advising for faculty.
- [x] `contracts/agent-manifests.yaml` and `src/agents/*/manifest.yaml` updated to match, via the contract-change flow.
- [x] Interpret's fallback agent is one the persona may use (`_default_agent` in `src/engine/graph/interpret.py`, tested in `test_interpret.py`).
- [x] `check_contracts.py` green; `uv run pytest src/engine -q` green.

## Partial resolution (2026-10-01, PR #2)

A routing probe ran 27 real UI prompts through the live classifier, with and without scope enforcement. 4 regressed. Two were fixed in the contract:

- `advising` persona_scope + `faculty` (faculty prerequisite checks were denied).
- `content_generator` persona_scope + `advisor` (advisor outreach plans early_alert → content_generator → communication lost their middle step).

Still open: admin "grading pipeline" and "credentials issued" questions now route to engagement_analyst instead of grading_assistant/assessment. Admin was deliberately not given those agents, because both carry ungated write tools (`assessments.commit_grade`, `assessments.approve_credential`) until Feature B's per-tool `allowed_roles` gateway lands. Revisit then: per-tool scoping replaces per-agent scope for this case.

## Closed (2026-10-02)

Applied in commit a4cf2dd: `advising` persona_scope widened with `faculty`, `content_generator` persona_scope widened with `advisor`. The admin grading and credential routes move to T-C-108. The write access this widening spread to `content.save_draft` and `content.save_skill` is narrowed by T-C-107.
