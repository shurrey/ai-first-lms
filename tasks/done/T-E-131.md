# T-E-131 — Object-level checks for tools keyed by submission_id or session_id

**Workstream:** engine
**Phase:** 1 (spec.md §19.1)
**Size:** M
**Status:** done
**Spec:** spec.md §4.4, §4.5, §5.2 step 3, §17
**Dependencies:** T-E-106

## Goal
The tool gateway scope-checks `person_id`, `student_id` and `course_id` only. Tools keyed by another id get no object-level check, so a faculty member using grading_assistant can read any submission by id.

## Context
- Affected today: `assessments.get_submission`, `assessments.commit_grade` (and an approver's edited `submission_id`), `roster.get_session_transcript`, and any tool whose only subject key is `submission_id` or `session_id`.
- Students cannot reach these agents, so nothing regresses; the gap is staff reading outside their courses.
- Align `assessments.approve_credential` approver coverage on the agent write-gate path with the REST rule (faculty of the course, or admin) when the §17 role tightening lands; today `_covers_course` also lets an advisor approve for a course containing an advisee.

## Acceptance criteria
- [x] The gateway resolves `submission_id` → (student, course) and `session_id` → (person, course) through the scope directory and applies `scope.can_view_student` before executing.
- [x] An approver's edited arguments are re-resolved and re-checked on resume.
- [x] A denial is a `denied_scope` tool result and a `guardrail` event.

## Tests required
- Gateway unit tests with fakes: faculty of another course gets `denied_scope` for a submission and a session transcript; own course passes.

## Closed
Verified against the Phase 0 security pass (`src/engine/guardrails/gateway.py`):
- `submission_id`: `_check_submission` resolves the owner via `assessments.get_submission` and the course via `ObjectDirectory.submission_course`, then applies `can_view_student` (used by `get_submission`, `draft_grade`, and `commit_grade` through the drafted grade's submission). `session_id`: `_check_session` resolves `ScopeDirectory.session_owner` → (person, course) and applies `can_view_student`.
- Approver re-check: `authorize_approver` re-runs identity, `_check_objects` and the course check as the approver; edits that change an identity key are `EditRejected` (`test_approver_is_object_scope_checked`, `test_edit_resumed_without_the_endpoint_is_rechecked`).
- Denials are `denied_scope` results carrying a guardrail payload, which the runner emits as a `guardrail` event.
- `approve_credential` on the agent path already requires faculty of the credential's course or admin (`_check_pending`), matching the REST rule.
- Gap closed: an invoke-level test for a faculty member of another course reading a session transcript (`src/engine/tests/test_access_log.py::test_faculty_of_another_course_is_denied_scope`); own-course passes are covered there and in `test_object_scope.py`.
