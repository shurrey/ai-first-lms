**Dependencies:** None (works with T-E-100)

## Goal
Let Linux containers trust the corporate root so truststore-based verification works inside `docker compose up`.

## Context
- Containers are `python:3.12-slim`; truststore there reads the container's OpenSSL store, which lacks the corporate root.

## Acceptance criteria
Copied from spec.md; the source section is in parentheses after each item.
- [x] `src/engine/Dockerfile`, `src/data_mcp/Dockerfile` and the `db-seed` service accept an optional build arg / mount `CORPORATE_CA_PATH` (a git-ignored PEM, default unset).
- [x] If present, it is copied to `/usr/local/share/ca-certificates/corporate-root.crt` and `update-ca-certificates` runs.
- [x] `SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt` and `REQUESTS_CA_BUNDLE` are set to the same path.
- [x] Off the corporate network (CA unset) the stock store is used. Both paths are documented in `docs/setup.md`.

## Tests required
- `docker compose build orchestrator` succeeds with and without `CORPORATE_CA_PATH` set.
