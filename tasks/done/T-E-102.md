## Goal

## Context

## Acceptance criteria
Copied from spec.md; the source section is in parentheses after each item.
- [ ] `POST /api/auth/login` sets `lms_session` (HttpOnly, `SameSite=Lax`, `Path=/`, `Secure`=`COOKIE_SECURE`, Max-Age=`SESSION_TTL_HOURS`, default 12) and `lms_csrf` (JS-readable), and returns the `/me` payload (§4.4).
- [ ] Failure returns `401` "Invalid username or password.", increments `failed_attempts`, and locks for `LOGIN_LOCKOUT_MINUTES` (5) after `LOGIN_MAX_ATTEMPTS` (5) failures; never reveals whether the username exists (§4.4).
- [ ] `POST /api/auth/logout` revokes the session and clears both cookies (§4.4).
- [ ] `GET /api/auth/me` returns `person`, `roles`, `active_role`, `enrollments`, `advisees_count`, `home_route`, `capabilities` (computed from §17) and `effective_ui_policy` (§4.4).
- [ ] `POST /api/auth/role` switches only to a role the person already holds; `403` otherwise (§4.4).
- [ ] `POST /api/auth/password` changes own password (current + new, minimum 12 characters) (§4.4).
- [ ] Dr. Torres can switch between Faculty and Program Lead. She cannot switch to Student, Advisor or Admin (§4.8).
- [ ] Five bad passwords lock the account for 5 minutes, and the error text does not reveal the lock or whether the user exists (§4.8).
