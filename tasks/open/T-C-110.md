# T-C-110 — Admin read of data_access_log: GET /api/access-log

**Workstream:** integration  (contract changes are never claimed by builder workstreams)
**Size:** S
**Opened by:** integration (Round 2 Phase 1, from the engine lane's T-E-113 work)
**Status:** open, awaiting approval
**Blocks:** T-E-113 acceptance item 2 (admin half), T-E-132, T-F-120

## What needs to change
- `contracts/api.openapi.yaml`: new `GET /api/access-log`.

## Why it's needed
spec.md §12.3 says the access log is visible to admins. The subject view is `access_log` in
`GET /api/me/data` (T-E-124, Phase 5). No contract endpoint lets an admin read it.

## Proposed change (draft)
`GET /api/access-log?subject_id=&resource=&from=&to=&before=&limit=`
- `x-required-capability`: an admin-only capability (or `active_role == admin`).
- `subject_id` required (uuid); `resource` optional, one of `transcript | profile |
  analyst_summary | submission`; `from` / `to` reuse `#/components/parameters/From|To`.
- 200: `{ entries: [{ id, actor: {id, display_name}, subject_id, resource, resource_id|null,
  purpose|null, created_at }], next_before: string|null }`, newest first.
- 401, 403 (non-admin), 422 (bad uuid).
- Reading the log is itself not logged (it holds no learner content).

## Impact
- Engine: T-E-132 implements it on `PgAccessLog.list_by_subject` (src/engine/auth/access_log.py).
- Frontend: T-F-120 adds the admin view.
- Breaking change: no. Migration: no.
