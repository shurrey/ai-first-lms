# T-C-121 — Formative-loop tools as served differ from the approved T-C-105 entries

**Workstream:** integration  (contract changes are never claimed by builder workstreams)
**Size:** S
**Opened by:** data-mcp (Round 2 Phase 2 review)
**Status:** applied on round2/phase2, awaiting approval

## Why it's needed
`contracts/mcp-tools.md` said "Change: T-C-105 — approved as planned" on entries whose served shape goes beyond
what T-C-105 approved. Those lines now name this task instead, so a reviewer can approve (or reject) each delta.
None of these deltas has been approved yet.

## Deltas beyond the approved entries (as applied on round2/phase2)
- `assessments.get_improvement`: input adds required `requester_id` (gateway-set; picks the view) and optional
  `criterion_id`; output adds `view`, `aggregate`, criterion `description` / `target_score`, student
  `display_name`, trajectory `key`. Requiring `requester_id` changes the planned input.
- `assessments.weaknesses`: input adds optional `window` (2–10, default 3); output adds `student_id`,
  `course_id`, `window` and per-weakness `target_score`.
- `assessments.release_feedback`: input adds `reviewer_id` (course faculty; required for edits and suppress) and
  `reason`; the server writes the `human_decisions` rows; output adds `suppressed` and `outcome_links`.
  Releasing a revision now writes its per-criterion `outcome_links` delta (moved here from save; see below);
  releasing a parent after its revision's feedback was already visible links that revision then.
- `assessments.save_criterion_feedback`: input adds optional `requester_id` (only the submitter or course
  faculty may save); output adds `ai_action_id`; released or suppressed criteria are a `conflict`. It no longer
  writes `outcome_links` (and its output no longer has `outcome_links`): a delta is linked only when its "after"
  score reaches the learner.
- `assessments.commit_grade`: committing a final revision writes its `outcome_links` delta with the instructor's
  `final_score` as `after`.
- `assessments.list_submission_history`: input adds `requester_id`; unreleased feedback and uncommitted final
  scores are masked unless the requester is course faculty (or an admin, for a `final` version only; a draft's
  unreleased feedback is for course faculty alone, spec.md §12.5), including when `requester_id` is omitted;
  rows add `course_id`, `feedback_status`; criteria add `description`, `level_label`, `ai_rationale`,
  `ai_evidence_spans`, `next_step`, `ai_action_id`.
- `assessments.grading_status`: output adds `due_at`, `ungraded` and `totals` to the T-C-112 draft.
- `assessments.propose_alignment`: input adds optional `criteria` (the agent's 3–6 drafted criteria, validated
  server-side) and output adds `proposal`, `assignment_title`, `course_id` and candidate `aligned`.
- `assessments.submit`: output adds `assignment_node` and `course_id`; one version chain per learner and
  assignment, with `conflict` / `forbidden` / `validation_error` cases.
- `content.generate_practice`: output adds `aligned_nodes` and `bank_id`; `bloom_level` / `difficulty` are
  enumerated in the input schema; an `mcq` needs `options`.
- `graph.subgraph_for_outcomes`: output adds `truncated` (500-node cap); the walk never passes through a
  `course` or `program` node.
- `assessments.search_bank`: never lists questions in a private practice bank (`question_banks.metadata.kind =
  "practice"`, spec.md §12.5), even when `bank_id` names one. Behavior change: a caller naming a practice bank
  now gets no rows.
- `assessments.list_recent_evidence` (not a T-C-105 tool; spec.md §12.5): input adds `requester_id`, output adds
  `visibility`; `private` evidence is returned only when `requester_id` is the learner. Behavior change for
  faculty, advisor and engine callers (engine-internal calls for the learner's own view must pass the learner).

## Impact
- Workstreams affected: engine (`requester_id` on `list_recent_evidence` calls made for a learner's own view;
  outcome_links now appear at release/commit, not at save), frontends (none beyond fields already consumed).
- Breaking change: `save_criterion_feedback` output drops `outcome_links` (no caller reads it);
  `list_recent_evidence` stops returning `private` evidence to non-self callers.
- Migration needed: no.
