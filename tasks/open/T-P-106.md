# T-P-106 — Fixed clock for recorded-fixture runs

**Workstream:** platform (with data-mcp and engine)
**Phase:** 1 follow-up (spec.md §20 E2E live)
**Size:** M
**Status:** open
**Dependencies:** T-P-105

## Context
Recorded LLM fixtures are keyed by request content. Timestamps are normalised, but several
tools filter on `now()` against a seed with absolute dates (semester starts 2026-08-24):
upcoming assignments (`due_at > now()`), evidence windows (`now() - N days`), "this month"
analytics, brief text. On a later day those tools return different rows, so a replay recorded
on one day misses on another. CI's `e2e-live-replay` therefore cannot be a required check yet.

## Interim state (2026-10-02)
Until this lands, recordings are not committed: `recordings/` is git-ignored, and
`e2e-live-replay` runs only on a manual CI run whose `fixtures_run_id` names a same-day
**Record LLM Fixtures** run (it replays that run's `llm-fixtures` artifact). See
`src/platform/llm-fixtures/README.md`.

## Progress (integration, round2/scenarios, 2026-10-02)
- The setting is `LMS_AS_OF` (`src/common/clock.py`), not `LMS_FIXED_NOW`; the overlay sets it
  for the seed, MCP servers and orchestrator, and also fixes `PII_PSEUDONYM_SALT` (pseudonyms in
  tool results were random per process, so they broke keys across runs).
- Remaining wall-clock reads in MCP servers and engine are write timestamps (`committed_at`,
  `issued_at`, `sent_at`, `created_at`); any that reach a model are ISO timestamps the fixture
  key normalises. Not proven by a replay on another date (no clock override in the containers).
- `run-live-e2e fill` (replay, record only misses, capped by `LLM_FIXTURE_FILL_MAX`) added.
- A set was recorded and replayed (0 network calls, bogus key); it does not replay green (see
