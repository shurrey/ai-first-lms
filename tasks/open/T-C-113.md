# T-C-113 — REST reject for a pending credential

**Workstream:** integration  (contract changes are never claimed by builder workstreams)
**Size:** S
**Opened by:** integration (Round 2 Phase 1, from T-E-110)
**Status:** applied on round2/phase2 (api.openapi.yaml and mcp-tools.md), awaiting approval
**Blocks:** T-E-133

## What needs to change
- `contracts/api.openapi.yaml`: `POST /api/reject-credential/{pending_id}` with
  `{ reviewer_id, reason? }`, same capability and scope as `/api/approve-credential`.
- `contracts/mcp-tools.md`: a reject path on the assessments server (new tool or a `decision`
  argument), so the pending row is closed.

## Why it's needed
A person can approve a badge from the credentials page, but can only reject one by rejecting
the agent's `approve_credential` approval in a chat turn. Without a REST reject, the
credentials page cannot record `human_decisions(rejected)` for badge recommendations (§6.4),
which skews the AI Review reject rate.

## Impact
- Engine: T-E-133. Frontend: a Reject button next to Approve on both credentials pages.
- Breaking change: no.
