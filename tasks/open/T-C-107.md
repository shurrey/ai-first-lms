# T-C-107 — mcp-tools.md: tighten write access on shared content

**Workstream:** integration
**Phase:** 0 (spec.md §19.1)
**Size:** S
**Status:** open (contract edit applied on round2/phase0, awaiting human approval)
**Spec:** spec.md §17, §5.2, §4.5, §18
**Dependencies:** T-C-106

## Goal
Grant write tools on shared course content only to the roles §17 lets edit course content.

## Context
- Security finding from the Phase 0 review: `contracts/mcp-tools.md` gave `advisor` write access to `content.save_draft` and `content.save_skill`, and `student` write access to both, without an approved contract change. The tool gateway reads Allowed roles from this file, so those lines were live permissions.
- The roles came from T-C-106 adding `advisor` to `content_generator`'s `persona_scope`, which the derived-union rule then spread to every tool that agent lists, writes included.
- A concept's skill document (`content.save_skill`) is shared: every tutor session on the concept reads it.
- `content.save_draft` reaches the same document. `node_id` and `kind` are free, and the content server's `get_skill` (no `is_draft` filter, no `ORDER BY`) and `retrieve` (newest row, drafts included) serve drafts. A draft with `kind = 'skill'` on a concept therefore replaces what tutors read. The gateway forces only `author_id`, so an "own drafts" qualifier on `student` would not have stopped this.
- The read additions that follow T-C-106 stay: `advisor` on `content.get_skill` and `content.list_skills`, `faculty` on `sis.degree_audit`.

## Change
- `content.save_skill`: Allowed roles `faculty`, `instructional_designer` (removes `student`, `advisor`).
- `content.save_draft`: Allowed roles `faculty`, `instructional_designer` (removes `student`, `advisor`). §17 gives students study aids for self only, which go through `content.generate_flashcards` (planned).
- Each carries a `- Change: T-C-107` line, so Allowed roles follows §17 rather than the persona_scope union.
- `check_contracts.py` gains a "shared-content write tools grant only approved roles" check, and only a Change line about `requires_approval` now excuses a doc/server approval mismatch.

## Acceptance criteria
