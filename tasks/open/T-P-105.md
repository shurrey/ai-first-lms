## Goal
The Chat UI scenario specs (scenario-1/3/10/11) log in with the real `login(page, username)` fixture and run against the live orchestrator with a recorded-response LLM fixture, instead of mocking `/api/auth/me` and the SSE stream.

## Context
Phase 0 added the live login fixtures but left the existing scenario specs on mocked sessions; that deferral was accepted on 2026-10-02 on the condition that this task does it properly.

## Acceptance criteria
- [ ] scenario-1, -3, -10 and -11 specs use the real login fixture; no mocked `/api/auth/me` or mocked SSE in them.
- [ ] They run in CI against a stack using a recorded-response LLM fixture (no API key needed), per spec.md §20.
- [ ] No mocked-event e2e test is the only coverage for any approval-gated flow (spec.md §22).

## Tests required
- The four specs green in CI.

## Files touched
- src/frontend/tests/e2e/*, .github/workflows/ci.yaml, recorded-response fixture location (engine test support).

  reproduces the recording run. They are not committed: `src/platform/llm-fixtures/recordings/`
  is git-ignored until T-P-106, because a set replays only on its recording day.
