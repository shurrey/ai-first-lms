## What needs to change

- `contracts/agent-manifests.yaml`: none (engine endpoint only).
- `contracts/api.openapi.yaml`: `POST /api/practice/{practice_set_id}/attempts` (the endpoint the UIs
  already call), `Submission.assignment_title`, `MeasurementSummary.practice` (`PracticeCounts`), and the
  practice and draft-feedback visibility rules on `/api/ai-actions*` and `/api/measurement/export`

## Why it's needed
spec.md §7.3 says "Student practice attempts → evidence rows (practice; private per §12.5)", and
`content.generate_practice` says attempts create `private` evidence, but no served tool writes an attempt, so a
practice set can be shown but never attempted, and the correctness of an answer cannot be checked against the
stored answer key (which only the server holds).

## Change (as applied)
### `assessments.record_practice_attempt`
- Mutates: true. Requires approval: false. Allowed roles: `student` (self).
- Input: `{ person_id: string, practice_set_id: string, answers: [{ question_id: string, answer: string }] }`
- Output: `{ practice_set_id, evidence_ids: string[], items: [{ question_id, correct: boolean | null,
  answer_key: object }], score: number | null }`
- Notes: only the student the set was made for may attempt it (`forbidden`); unknown set `not_found`; an answer
  to a question outside the set is a `validation_error`. `correct` is a trimmed, case-insensitive match with
  `answer_key.correct` (value or list), null when the key has no `correct`. Writes one `evidence` row per aligned
  outcome node: `kind attempt`, `source practice`, `visibility private`, payload
  `{ practice_set_id, answers: [{ question_id, answer, correct }], correct, checked }`.

## Impact
- Workstreams affected: data-mcp (implemented), engine (endpoint mapping the UI's `item_index` to `question_id`,
  `correct_answer` from the returned `answer_key`), frontends (already call the endpoint).
- Breaking change: no. Migration needed: no.

## Applied (2026-10-03, branch round2/phase2 (engine lane)) — awaiting approval
`contracts/api.openapi.yaml` changes:
- New `POST /api/practice/{practice_set_id}/attempts` (`recordPracticeAttempt`, schema `PracticeAttempt`).
  - Student role and the set's own learner only (its `practice_item` ai_action's `subject_person`): another
    learner's set is 404, any other role 403. `practice_set_id` is the practice_item ai_action id.
  - Body `{ answers: [{ question_id: uuid, answer: string (≤ 5000) }] }`, 1–20 answers, no question twice.
  - Proxies `assessments.record_practice_attempt` with the caller as `person_id`; tool errors map to
    404 / 403 / 422, else 502.
  - Response 201 `{ practice_set_id, attempt_id, results: [{ question_id, correct, expected, feedback }],
    correct, total }`: `expected` is the stored `answer_key.correct` (accepted values joined with " or "), else
    `model_answer` or `model_points`; `feedback` is `answer_key.explanation`; `attempt_id` is the first private
    evidence row written (null when the set has no aligned outcome).
- `Submission` gains `assignment_title` (string | null, the assignment node's title); every submission
  serializer fills it (the UIs showed "Assignment" for every row).
- `MeasurementSummary` gains `practice` (`PracticeCounts { generated, started, dismissed }`): practice sets are
  counted, never rated (spec.md §12.5: faculty see aggregate counts only).
- `/api/ai-actions*` scope note: practice_item rows and their decisions appear only to their learner (404 on
  the detail for anyone else); criterion_feedback on a draft submission only to its learner (once released) and
  faculty of its course; learner and advisor views carry only the outcome_links whose observed side the learner
  can see (attestation, course-visible evidence, released or committed criterion score) on a criterion the
  learner-view output scores, with a criterion link's `before` / `after` / change replaced by the scores the
  learner sees now. The outcome linker links a criterion only once both sides are learner-visible (committed
  final_score, else released ai_score).
- `GET /api/submissions/{id}/history`: an admin sees the learner's view of draft versions (faculty of the
  course still see every score).
- `/api/measurement/export`: practice items never exported; draft criterion_feedback only to course faculty.

## `roster.get_student_context` withholds private evidence (applied on round2/phase2, awaiting approval)

The attempt rows are `visibility: private`, but `roster.get_student_context` reads evidence with no
visibility filter, so a learner's practice score could reach the faculty / admin / advisor gradebook brief and
the `early_alert`, `tutor`, `advising` and `communication` agents. Proposed contract change, mirroring
`assessments.list_recent_evidence`:

- Input gains `requester_id?: string` (the gateway forces it to the caller once the contract declares it).
- `recent_evidence` omits `private` evidence unless `requester_id` equals `person_id`; output rows gain `source`
  and `visibility`.

Engine side (done here): every page/session brief call to `roster.get_student_context` sends the viewer as
`requester_id`. For a viewer other than the learner, the brief and the tool gateway (agent calls) keep only
`recent_evidence` rows tagged `visibility: course` or `program` and not `source: practice`; an untagged row is
treated as private (`src/engine/guardrails/private_evidence.py`; tests in `src/engine/tests/test_brief.py` and
`src/engine/tests/test_private_evidence.py`).

Applied (2026-10-03, branch round2/phase2, regression pass): `contracts/mcp-tools.md` `roster.get_student_context`
now declares `requester_id?` and returns `source` / `visibility` on every `recent_evidence` row; the server
(`src/data_mcp/mcp_servers/roster/tools.py`) leaves out `private` rows unless `requester_id` is the learner. The
gateway therefore forces `requester_id` to the caller for the `early_alert`, `tutor`, `advising` and
`communication` agents. Staff gradebook briefs get the learner's course-visible evidence again (committed grades).
Tests: `src/data_mcp/tests/contract/test_formative.py`
(`test_practice_evidence_reaches_student_context_only_for_the_learner`,
`test_student_context_keeps_course_evidence_for_staff`).

Also applied: an attempt on a practice set with no aligned outcome node is kept as one private evidence row on
the criterion's assignment node instead of being dropped (`evidence_ids: []`).
