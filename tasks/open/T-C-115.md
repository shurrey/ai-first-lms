# T-C-115 — `final.payload.ai_action_ids` and a length cap on decision reasons

**Workstream:** integration  (contract changes are never claimed by builder workstreams)
**Size:** S
**Opened by:** engine (Round 2 Phase 1 review fixes)
**Status:** applied on round2/phase1, awaiting approval

## Why
- The Chat UI reads `final.payload.ai_action_ids` (`src/frontend/lib/events.ts`,
  `ChatPane.tsx`) to link a turn's generated items to their provenance, but no contract
  defined the field and the engine never sent it, so the links were always empty.
- `POST /api/ai-actions/{id}/decisions` accepted a `reason` of any length. Reasons are stored,
  shown in AI Review and written to the evaluator CSV export.

## What changed
- `contracts/events.md` — `FinalPayload` gains `ai_action_ids: string[]`: the ids of the
  `ai_actions` rows written during the turn, each once, in the order written (including rows
  for actions declined at approval); `[]` when none.
- `contracts/api.openapi.yaml` — the decisions request body's `reason` gets `maxLength: 2000`;
  a longer reason is a 422 (the existing `ValidationFailed` response).
- `contracts/api.openapi.yaml` — the `x-scope-check` of `GET /api/ai-actions` (and, by
  reference, `GET /api/ai-actions/{id}`) documents the learner view: student and advisor see a
  grade draft only once its grade is committed, criterion feedback only once released, no
  rejected drafts, and no decision diff or reason; the detail endpoint answers 404 for a hidden
  item. Behaviour change, no schema change.

## Engine implementation (already on the branch)
- `src/engine/streaming/events.py` `FinalPayload.ai_action_ids`.
- The provenance recorder lists the rows it writes per tool call; the gateway collects them on
  the step's `GatewayContext.ai_action_ids`; dispatch puts them on the step's `AgentResult`;
  synthesize emits the de-duplicated union on `final`.
- `src/engine/api/decisions.py` `DecisionBody.reason` has `max_length=2000`.
- `src/engine/measurement.py` `visible_to_learner` / `learner_visible`; `src/engine/api/measurement.py`
  applies them, and drops diffs and reasons, for the learner view.
