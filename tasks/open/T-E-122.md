## Acceptance criteria
Copied from spec.md; the source section is in parentheses after each item.
- [ ] Issuer profile from `system_settings` replaces `urn:uuid:ai-first-lms`; issuer id is a `did:key` from the signing key (§11.4).
- [ ] Ed25519 key pair generated on first run into `BADGE_SIGNING_KEY_PATH` (default `./.keys/badge_ed25519.pem`, `.keys/` git-ignored); credentials get an `eddsa-rdfc-2022` Data Integrity proof, or VC-JWT (`EdDSA`) documented in `docs/decisions/badge-signing.md` if no maintained canonicalization library exists (§11.4).
- [ ] `GET /api/credentials/verify` returns signature validity, issuer and revocation status (§11.4).
- [ ] `issued_credentials.revoked_at` / `revocation_reason`; revocation is write-gated (admin or issuing faculty) (§11.4).
- [ ] `CredentialProvider` interface; `FileExportProvider` (default) writes to `./exports/credentials/`; `CredlyProvider` / `BadgrProvider` behind `BADGE_PROVIDER`, tested with HTTP mocks only; `external_id` populated when returned (§11.4).
- [ ] A badge approved by Dr. Torres verifies as valid through `/api/credentials/verify`. Tampering with one field makes it invalid (§11.7).
