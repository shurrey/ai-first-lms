# T-C-109 — Document Phase 0 security behaviour in mcp-tools.md and api.openapi.yaml

**Workstream:** integration  (contract changes are never claimed by builder workstreams)
**Size:** S
**Opened by:** engine (Phase 0 security regression pass)
**Status:** drafted on round2/phase1, awaiting approval
**Blocks:** none (the engine already enforces everything below; this brings the contract text in line)

## What needs to change
- `contracts/mcp-tools.md`: the "Allowed roles" preamble, and Notes/Allowed roles on
  `assessments.approve_credential`, `assessments.get_credential_evidence`, the three
  `analytics.*` tools, `attestations.attest`, `roster.save_concept_review` and `content.save_draft`.
- `contracts/api.openapi.yaml`: descriptions on `POST /api/auth/logout` and `POST /api/auth/password`.

## Why it's needed
The Phase 0 security fixes added gateway object-level checks and auth lockout behaviour that the
contract text still describes as absent or does not mention. No status code or schema changes:
the engine returns only codes the contract already lists.

## Proposed change (draft)

### mcp-tools.md preamble ("Allowed roles" bullet)
Replace "a tool keyed only by another id (`submission_id`, `session_id`, ...) gets no
object-level check yet." with:
"The gateway also resolves these ids to an owner or course and scope-checks them:
`submission_id` (`get_submission`, `draft_grade`), `grade_id` / `draft_id` (`commit_grade`,
`send_message`, through the drafting turn), `pending_id` (`approve_credential`,
`get_credential_evidence`), `session_id`, `concept_id` (`content.save_skill`), `node_id`
(`content.save_draft`), `bank_id` (`create_question`), the `communications.draft_message`
audience, and every `analytics.*` scope."

### assessments.approve_credential
Allowed roles: `faculty` (of the credential's course), `admin`. Drop `advisor` and
`instructional_designer`; add `- Change: T-C-109 — matches /api/approve-credential; the gateway
already refuses both at the scope step.`

### assessments.get_credential_evidence
Drop `instructional_designer` (the gateway always refuses it: `can_view_student` gives that role
no learner view), or define a course-staff rule for designers. Add a Change line either way.

### analytics.query / analytics.trend / analytics.cohort_compare
Notes: "For non-admin callers the gateway refuses unbounded scopes. Every scope the server filters
by (the top-level scope, or each cohort scope merged over it) must name a course the caller can
act in for faculty, and an advisee `person_id` for advisors. A course alone is refused for
advisors; a learner alone is refused for faculty."

### attestations.attest / roster.save_concept_review
Notes: "For a `student` caller the gateway overwrites `session_id` with the caller's current
session, and refuses the call when there is none."

### content.save_draft
Notes: "When `node_id` is set, the gateway requires a course the caller may act in: the node
itself as a course, or its `part_of` chain (concept or skill, module, course)."

### api.openapi.yaml
- `POST /api/auth/logout`: "A missing, expired or revoked session also returns 204 with both
  cookies cleared."
- `POST /api/auth/password` 400: "Wrong current passwords count toward `LOGIN_MAX_ATTEMPTS`."
  401: "Also returned, with both cookies cleared, by the attempt that trips the lockout; that
  attempt revokes the calling session."
